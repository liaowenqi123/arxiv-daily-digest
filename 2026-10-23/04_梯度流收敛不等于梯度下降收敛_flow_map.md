# 2026-10-14 · 梯度流收敛 ≠ 梯度下降收敛|On the Stability and Convergence of Flow Map Training

> arXiv:2610.20674 · 提交:2026-10-14 · Ishan Nath, Tom Stanic, Avishek Joey Bose, Gauthier Gidel, Quentin Bertrand(Inria / Mila / Imperial)
> 一句话:flow map 训练里的 stop-gradient 和自适应权重不是炼丹技巧,而是"梯度流能收敛、梯度下降会爆"这两件事之间的必需品。

## 〇、人话版(先看这个)

- **输入**:一个噪声样本 $x_0$、起始时刻 $s$、目标时刻 $t$。
- **输出**:一步把 $x_0$ 送到 $t$ 时刻样本位置的映射(flow map),用来做**一步生成**。
- **任务**:**生成建模**(学一个从噪声到数据的变换),不是预测、不是分类。训练目标是回归"平均速度场"。
- **老问题**:这类训练离不开 stop-gradient 和自适应权重两个技巧,有效但没人说得清为什么;而且 loss 不降到 0,被质疑"目标里有假极小"。
- **它改了什么**:把目标放到**函数空间**看。证明 ① stop-gradient 版的梯度流**仍然收敛到真 flow map**(所以不是假极小);② 但真正做有限步梯度下降时,梯度里的微分算子**无界**,误差被放大,任意步长都能构造发散;③ 自适应归一化(指数 $p\ge0.5$)是唯一能压住的办法。
- **凭什么更好**:图像 FID 在 $p=0.5$ 处出现断崖(10.62 → 5.51),与理论阈值精确对上;合成实验里学到的映射与闭式解逐点吻合。
- **代价**:理论假设精确梯度、无随机、无架构约束;实验是图像 U-Net,时序未验证。
- **类比**:开车。理论上"顺着路慢慢开会到";但方向盘稍微一动就被放大,车飞出路面。不是路修错了,是**方向盘增益无界**。限幅才开得稳——这就是 $p\ge0.5$。

**作者核查**:Gauthier Gidel(Mila 教授,优化/博弈论背景)、Joey Bose(Imperial/Mila,扩散与 flow)、Quentin Bertrand,都是圈内可查的研究者;一作 Ishan Nath 是较新的合作者。理论部分可信度:**较高**;但这是 preprint,未见独立复现。

## 一、它在跟什么较劲

一步生成(flow map / 一致性模型)现在人人都在用几个 trick:stop-gradient 目标、loss 重加权、梯度归一化、手挑时间对分布。但没人说清**为什么**。更麻烦的是两个"反证":

- MeanFlow 的 loss **不收敛到 0**,有人据此说目标里有假极小(Goldstein et al., 2026);
- stop-gradient **改变了梯度方向**,理论上完全可能收敛到错的地方。

于是实践处于一种尴尬状态:技巧有效,但理由是"经验上有效"。

## 二、核心思想(机制层)

作者把问题放到**函数空间**(L² 内积、Fréchet 导数)里看,得到三层结论:

### 1. 梯度流确实收敛,而且有闭式解

对 MeanFlow 与 Lagrangian 两个目标,梯度流 $\partial_\tau u_\tau=-\nabla_u L(u_\tau)$ 的解可以写成:

$$\Phi^{\text{MF}}_\tau(x,s,t)=\Phi_0\big(\Phi^\star(x,s,t_\tau),\,t_\tau,\,t\big),\qquad t_\tau\uparrow t$$

$$\Phi^{\text{L}}_\tau(x,s,t)=\Phi^\star\big(\Phi_0(x,s,s_\tau),\,s_\tau,\,t\big),\qquad s_\tau\downarrow s$$

**读法**:训练过程就是**逐步把"初始化估计的那段剩余跳变"替换成真实 flow**。MeanFlow 从后往前替换($t_\tau$ 增大),Lagrangian 从前往后替换($s_\tau$ 减小)。两者都收敛到真 flow map,只是从相反方向逼近。

这一条直接回答"stop-gradient 会不会学错":**不会**。它改了梯度方向,但改后的方向仍然把 map 推向 $\Phi^\star$。loss 不降到 0 也不矛盾——函数空间里收敛的对象是 **map**,不是逐点残差。

### 2. 但梯度下降会爆,而且不是学习率的问题

梯度里含有微分算子($\nabla_x u$、$\partial_s u$),在 L² 上**无界**,会把误差放大。Proposition 1:对**任意**步长 $\eta>0$、任意小的初始误差 $\varepsilon$,都存在一个 $u_0$,使 GD 迭代发散。

**这就是全文最值钱的一句**:flow map 训练的不稳定是**算子性质**,不是超参没调好。调小学习率救不了。

### 3. 自适应归一化是必需的解药

把更新写成

$$u_{k+1}=u_k-\eta\rho\,\frac{r_k}{(\|r_k\|^2_{L^2(\rho)}+c)^p},\qquad r_k=u_k-u_{\text{tgt},k}$$

- $p\ge 0.5$:更新**一致有界**;
- $p=1$:收敛到真解的一个 $O(\sqrt\eta)$ 邻域(Theorem 4);
- 而 MeanFlow 原文用的正是"按残差大小归一化"的权重,对应 $p=1$。

**于是那个"经验上有效"的 trick,被解释成了"唯一能让离散迭代不发散的选择"。**

## 三、为什么反直觉 / 优雅在哪

- **反直觉**:大家以为不稳定来自"目标设计得不好"或"学习率太大";真实原因是**梯度算子无界**,这是目标本身的解析性质,换目标也躲不掉(只要它还含微分算子)。
- **更反直觉**:stop-gradient 这种"故意不算梯度"的操作,通常被当成近似/妥协;这里它恰恰是让梯度流收敛的那个选择。
- **优雅**:没有提出新模型、新损失、新架构。只是把已有 trick 放进函数空间重讲一遍,得出一个可检验的常数 $p=0.5$。
- **判据**:如果实验里 $p<0.5$ 并不明显变差,那"有界性"就只是形式上的装饰。他们的实验正好在 0.5 处有一个断崖。

## 四、关键证据

**图像(FID,CIFAR-10,NFe=1)**:

| $p$ | 更新有界 | FID ↓ |
|---|---|---|
| 0.00(原始 GD) | ✗ | 10.62 |
| 0.25 | ✗ | 6.81 |
| **0.50** | ✓ | **5.51** |
| 0.75 | ✓ | **5.46** |
| 1.00 | ✓ | 5.61 |
| 1.50 | ✓ | 6.32 |

FFHQ 64×64 同样:$p<0.5$ 明显更差,$p=0.5\sim1$ 最好。**断崖位置与理论预测的 0.5 完全对上**,这是比"我们也涨点了"强得多的证据。

**合成实验**:在真 flow map 可解析计算的情形下,训练到中间时刻学到的 map 与 Theorem 1 的闭式解**逐点吻合**。理论不是事后解释,是预测。

## 五、边界与可疑处

- 分析假设**精确梯度、无随机性、无架构约束**。真实训练是 SGD + 小网络,理论是理想化极限。
- $p=1$ 的结论是"收敛到 $O(\sqrt\eta)$ 邻域",不是收敛到零;所以"loss 不降到 0"依然成立,只是不再是问题。
- 图像实验用 EDM2 U-Net,和时序小模型差距很大;结论能否迁移未知。
- Lagrangian 的非线性 PDE 证明依赖额外正则假设,比 MeanFlow 那半部分弱。
- Preprint,work in progress;没看到独立复现。

## 六、对我们有什么用

这条基本是 Drifting / 1-NFE 的**安全带**,有三个直接后果:

- **必须问同一个问题**:我们的 drifting 目标(以及任何自举/stop-grad 目标)是否存在"梯度流收敛但 GD 发散"?检查方式很便宜:看更新范数 $\|u_{k+1}-u_k\|$ 随训练是否出现尖峰,以及把 $p$ 从 0 扫到 1.5。
- **可直接借的配方**:用 $\|r\|^{-p}$ 归一化,默认 $p=0.75$(实验最优点),并**报告 $p$ 的敏感性**。审稿人问"为什么这么设",现在有理论答案。
- **可证伪的小实验**:在时序/金融数据上把 $p\in\{0,0.25,0.5,0.75,1,1.5\}$ 各跑一次,看 CRPS 是否在 0.5 处出现拐点。
  - 出现:说明我们的目标同样有无界性,归一化是承重件;
  - 不出现:说明我们的目标结构不同(也是有用的信息,写进论文就是"我们的目标不依赖该 trick")。

**只能当反面教材**:不要再用"我们的 loss 不收敛到 0"来质疑 flow map 类方法——这篇已经把这件事解释掉了。

## 七、值得抄的一句话

> "We highlight a severe roadblock to the usage of these losses in practice: the possible unboundedness of the update."

> 我们指出这些损失在实践中使用的一个严重障碍:更新可能无界。
